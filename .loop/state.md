## 未固化教训

- **`git worktree add` 不继承 gitignored 内容,委派 briefing 必须自包含**(v0.9.15 实锤):派进 worktree 的 codex 子会话(PLUGIN/SURFACES)两个都报告 `docs-local/versions/v0-9-15/*` 在它们的工作目录里「不存在」——worktree 是从 git 对象库检出的,gitignored 文件从来只活在**某一个**工作目录的文件系统里,新 worktree 天生看不到。两个子会话都靠 prompt 里内嵌的完整 spec 正确交付,证明了纪律本身有效,但这是运气好(我把 spec 写得够全),不是必然。**同形待扫**:任何要点名 `docs-local/`(PRD、W0 探针、decisions)的委派 briefing,若目标不是主工作树,要么把关键内容**转述进 prompt**(本次做法),要么显式 `cp -r` 把该目录同步进新 worktree——不能假设子会话「读得到」。
- **secret 经子进程 env 传递 = 默认被子进程的子进程继承,必须读一次即删**(v0.9.15 D19 实锤,W0 真机探针发现,非设计阶段能预判):tech-design 草稿早就写了「secret 只在 host 插件进程 env / 内存,不得进 sandbox bash」,但**没写怎么保证**——真机探针 #19 一测就漏:`CCTEAM_MCP_BEARER` 留在 `process.env`,DSH 自己的 bash 工具子进程(Node `child_process` 默认继承父 env)照单全收。修法是纪律不是补丁:插件 `apply()` 读一次该 env 存进闭包变量后**立即 `delete process.env.X`**,发生在 boot 阶段、早于任何可能触发子进程的 turn。**同形待扫**:凡「把只想给某一层用的密钥放进 `process.env` / 子进程环境变量」的地方,都要问「这个进程还会再 spawn 别的子进程吗?它会不会也看见」——env 是继承性的,不是作用域性的,default 是泄漏不是隔离。
- **「把凭据交给 vendor」不等于「vendor 用了它」——契约之外的东西只能测量,不能断言**(v0.9.14 三连实锤):`mcp_config.rs` 里写着「受管会话用自己的 principal 压过同名全局条目」,claude(`--strict-mcp-config`)与 codex(per-thread 深合并)成立,**ACP 面根本没有同类物**;真机 4/4 受管 grok 装载的是它自己 `config.toml` 里的同名条目,而 daemon 侧只看到 `tier=enroll:…`。更刺的是隔离复现里**注入方 3/3 获胜** —— 配置内容、cwd、plugin-dir、argv[0]、inbound policy、daemon env 全复制都没能重现生产的失败,这本身就是结论:**ACP-vs-config 优先级不是契约**。改法不是继续在 vendor 的地盘上找开关(六个 compat env、两级 `[plugins].disabled`、`--plugin-dir` 遮蔽先例全部实测失效),而是①把 outcome 变成**记录**(principal 首次使用;两条路都没到才 `identity_degraded`,broadcast-only 不入 chat)②换到 ccteam 说了算的战场:**进程血缘**(daemon 亲自 spawn 的子进程,pid 在第一个握手字节前就登记,loopback peer 经 `/proc` 上溯)。判据:**凡「我们把 X 交给 vendor 并假定它会照做」的地方,都要能回答「怎么知道它做了」**。
- **同一个资源在写路径与读路径被当成两种东西 = 一半的修复**(`b6a2b87d` 实锤,「同形扫一遍」的又一战果):codex app-server 重启后,写路径把连接当**可重建资源**(`client()` 重拨 + `ensure_thread_loaded` 重挂线程,agent 照常提交、照常 push),读路径却把 `events()` 当 spawn 时一次性拿到的**事实** —— 于是会话在每块面板上 🔵 working 了 2.5 小时,每个 turn 都死在上游,父会话等一个永远不会来的完成。修在契约(`events` 可重复调用 + `event_attachment()` 无默认实现)而非某个 adapter,故第七个 vendor 必须表态。**扫法**:找「spawn 时取一次、之后一直用」的句柄(`let mut events = …`、缓存的 client、缓存的 socket),问一句「承载它的东西死了会怎样」。
- **ccteam 自己的自愈动作可能就是病根**(`573819ba`):`prime_tool_surface` 发的 `mcp_reconnect` 让 claude **重新解析** server 列表且不再尊重 `--strict-mcp-config`,于是受管会话在启动发现期用自己的 principal 认证一次(所以「从未用过 principal」的守卫沉默),此后整生命周期以机器身份说话(现场 8/8 tool call)。教训:**给「修复动作」也写一条 before/after 的实测**,尤其是那些「重连/重载/重建」类动词 —— 它们通常等价于「重新走一遍初始化」,而初始化的入参未必还在。
- **vendor 的能力边界会变,所以判据要接到 vendor 自报的信号上,别接到硬编码表**(`7a58989c` 实锤):`outlives_turn` 用 `task_type` 白名单推断「这任务是不是后台的」,claude 把 `Agent` 改成异步启动那天,这张表就开始撒谎——而且是**沉默地**撒谎(每个异步 agent 被 turn 结束的安全网清掉,`/status` 里凭空消失,`local_bash` 恰好在表里所以后台 shell 还活着,更像"只是 agent 有问题")。改法不是往表里再加一行,是换信号源:claude 每次变更都重发全量 `system:background_tasks_changed`,认它。**同形待扫**:凡「我们推断 vendor 的内部状态」的地方(任务是否后台 / turn 是否在飞 / 会话是否 idle),都要问一句「vendor 是不是已经在说了,而我们没听」。
- **同一个提交里新增的机制,要先问「已有的行能不能承担」**(`652e2d38` 收 `e541e557` 的矛盾):为了关掉死 turn 的忙窗新加了 `chat_turn_failed` 事件种类,同时又把 `TurnFailed` 折进共享终结记账投影——于是一个失败 turn 写**两条**终结行,自带的测试还断言了与实际相反的行为。判决是**净减**(删掉新加的种类,让共享记账行当唯一终结边界)。教训:加 schema 种类前先枚举既有终结路径;新种类与既有投影**同时**覆盖同一事件 = 双写,必然有一处断言是假的。
- **「构建成功 ≠ 已部署」:修复的验证必须核到运行中进程的 build sha**(2026-07-31 rob 租户 `/status` 实锤):「同一 bug 修过两次仍复现」的病根不在代码 —— 48bd3c81/e6fbef72 正确且测试绿,但从未接管活 daemon:①本机 `CARGO_TARGET_DIR=/data/.local/cargo-target` 重定向产物,部署软链 `~/.local/bin/ccteam → repo/target/release/ccteam` **生来断链**;②daemon(efce019,Jul-29 起)从未重启,`/proc/<pid>/exe` 指向已删旧映像;③PATH 前列还有 Jul-2 旧拷贝 `/data/.local/cargo/bin/ccteam` —— 三个 binary 三个真相。纪律:声称「已修复」前必对齐 `ccteam --version`(磁盘)与运行中 daemon 的 build(`/proc/<pid>/exe` 拷出来跑 `--version`);本机部署 = **实体拷贝**安装,禁软链构建产物。产品化防复发 = DEPLOY-DRIFT-1(daemon 外显 build sha + doctor 漂移告警)。
- **vendor 报告的 turn 结局是数据,静默降级为「成功」= 契约腐蚀**(`410647d` 实锤,建议升为 adapter 契约条目):ACP `session/prompt` 即使 turn 被拒绝/截断/取消,返回的仍是**成功的 JSON-RPC 响应**,`stopReason` 是协议里唯一说明结局的字段——而它在全仓从未被读(grep 只命中测试 fixture)。后果不止 UX:半截前言当最终答案落 `turns.jsonl`,委派 parent 被告知任务完成(`vendor_error:false`),即**账本与完成通知同时说谎**。修在共享 `acp/` 层(`AcpStopReason`)故新 ACP vendor 自动被覆盖(符合「新入口自动覆盖」判据);缺失字段必须判 clean(否则回归 grok/opencode)。**同形待扫**:凡「vendor 给了结局字段而我们只取内容」的消费点(claude `subtype`、codex `will_retry` 已处理;其余 adapter 待核)。
