## 已固化的架构决定(D1–D5,**不重新讨论**)

- **D1 Rust 单 binary**:orchestrator + CLI + hooks 都是 `ccteam` 子命令;Cargo workspace 三 crate(`ccteam-core` / `ccteam-cli` / `ccteam-hooks`);默认 dep:`tokio` / `clap` derive / `serde` + `serde_json` / `tracing`。
  - **重要**:若 development-plan / tech-design 文字里仍写 `asyncio` / `Python 脚本`(M0.6 文档遗留),按 D1 实际用 `tokio` / Rust——文档与实现冲突时**实现按 D1**,可顺手在 PR 里把文档同步改了。
- **D2 可插拔前端**:M0 只做 CLI + tmux 三 pane;ratatui TUI / xterm.js+axum web 是 M3+ / M4+ 机会主义,**M0 不实现**。
- **D3 前端层 invariant**:任何前端不引入新 LLM 层;LLM 只在 L0(用户自带 claude)+ L2(项目级 tmux 内 claude)。
- **D4 用户对话入口**:M0 仅 CLI `--format json`(M0.11 实现);M1+ 加 `ccteam-control` skill;M2+ 加 `ccteam-mcp`。
- **D5 参考实现**:`references/agent-of-empires/`(Rust + ratatui + axum ws + tokio + tmux 包装)。**基础设施层全抄**——前端栈(ratatui / axum ws)、**tmux session 管理(起停 / send-keys / detach,M0.7 重点参考)**、Cargo dep 选型、CLI 框架风格都直接借鉴。**业务逻辑不抄**——9-phase 编排、Seed Gate、跨项目 RAG、Defense in Depth 是 ccteam 差异化护城河。先 grep `references/agent-of-empires/src/` 找 tmux / session / pty 关键字,有现成代码就抄结构(不必逐字复制)。

## 通用纪律

- **抄不发明**:先 grep `references/agent-of-empires/` + `~/.claude/plugins/marketplaces/claude-plugins-official/<plugin>/`(CLAUDE.md §3.7 三档复用粒度)
- **不引入 Python / Bash 运行时依赖**(D1)——hook 是 `ccteam hook <name>` 子命令,不是独立脚本
- **PR 纪律**(CLAUDE.md §五):commit 必须能映射 M0.X 任务编号 + requirements 痛点;改协议(YAML / JSON / 文件路径 / CLI 签名)**必须同步** `interfaces.md` 对应章节
