group 图例(分组语义)

  • entry = 用户 / IM 入口。
  • control-plane = Control 单例(IM 收口 + web + 调度 + 注册表 + CA),ZERO pane 计算,纯 I/O 路由 + 聚合读 ⇒ 一台弱机也能领一队强机。
  • worker = 每台执行节点(= 今天 daemon MINUS IM listener),独占自己 session。
  • vendor = Claude/Codex 进程 + per-machine 登录。
  • shared-state = 文件/JSONL;可中心化的是派生 INDEX,owning Worker 才是写者。

执行不可迁移的三条硬绑定(已读码核验)

  • gateway 持非序列化 Arc<dyn HarnessAdapter> + ThreadHandle(重启 resume_thread 重连本机 pane)。
  • Anthropic transcript 在本机 ~/.claude/projects/ → 靠本机 inotify tail。
  • hook 回连 + in-pane MCP forwarder 走本机 AF_UNIX mcp.sock / hook.sock(UDS 不跨主机)。
  • 故 turn 必在 owning node 跑,只 DATA + CONTROL 过 mTLS。rmux RmuxEndpoint 虽 #[non_exhaustive] 留了 TCP,本版不走 remote-backend 路线。

sid 命名空间 = n-<node>:s<N>

  • Worker 自铸 s<N>(保留 next_session 单调计数器,不 round-trip Control mint id)⇒ burst fan-out 不被序列化。
  • 节点前缀使命名空间正交、ownership 编码进 id(prefix==node_id 即 owner)。
  • 本机 turn 字节级同今天(零 lookup,见绿色虚线热路径);跨机才解析前缀。
  • 本地 s<N> 仍是 pane / turns / marker 键(chat_session_name / CCTEAM_CHAT_SID 零改)。

单点诚实 + --role both 退化

  • Control = 单点(IM/web 入口 + placement,无 HA,本版 defer)。
  • Control 宕 = 入口宕,但每个 Worker live session 继续跑(永不被 kill)且经自己 standalone /api/v1 + web 仍可驱动 ⇒ degraded,not dead。
  • Control 重启从 machines.yaml + 下轮 heartbeat 重建全局视图(Worker 是 SoT,Control 可重建)。
  • --role both(默认单机):Control+Worker 折叠一进程、loopback、无 mTLS、省 node 前缀 ⇒ 与今天 daemon 字节级一致,1-2 机用户零行为变化。

安全边界:过网只有 daemon↔daemon;本机回路永不跨网

本版交付 Tier 1 传输机密性(TLS,硬 blocker:今天 7331 是明文 http) Tier 2 机器身份 = mTLS(per-node client cert,proof-of-key-possession,非裸 bearer) Tier 3 in-pane→daemon 刻意留本机(session 钉 owning node,此回路永不跨网) 跨机特权边界(真边界:op 来自 Control mTLS 链路 + Worker 间不互相通信) fleet 级 cost-cap 聚合强制
fail-closed 前提(硬 gate):acl 空 allowlist 翻 fail-closed · Slack stub 补真 HMAC · ~/.ccteam/run 收紧 0700 DEFER:per-agent 沙箱隔离 DEFER:Control HA / failover DEFER(给 fail-closed 退路):跨机 HITL 强化 DEFER:自动跨机 clone repo
  • 单一信任域声明:enroll 一台 Worker = 「我信任它如同我的 Control 机」。整队属同一个人 — 不假装多租户;星型(Worker 间不通信)已把横向爆炸半径压到比 mesh 小。
  • 机器凭证(cert)≠ 人的 web-token:web-token 是单一共享明文(ccteam status 明文打印 + 自动复制剪贴板),绝不复用当节点间凭证;cert 独立类、永不打印、可 ccteam cluster rotate 轮转。
  • per-session secret 在目标 Worker 本地 mint 注入本地 pane env,绝不过线 ⇒ 保住(承认是 best-effort 的)gate 语义 per-node。
  • 硬 ship gate:若 server-TLS + cert-pin 这版排不进 scope,正确动作是 DEFER 跨机特权控制,只发单机 + 只读聚合视图(Phase A)+ 文档「联邦需你自备私网(wireguard/tailscale)」;绝不在明文上发特权跨机控制面。

能力派活(placement)+ 并行度拉满

  • 三入口同一函数:IM /new <project> [--on <tag|node>] · web create-modal placement picker · cto session_spawn{placement} — 全 funnel 进 place_session()。
  • 匹配:filter 到 {require tags} ∩ {vendor available 且 login_ok 且 version-ok} ∩ {repo 在该 node} ∩ {未触 cost-cap、未满 max_parallel} 的 node。
  • 负载均衡:幸存者按 headroom_score = w1·空闲并行度 + w2·(1−load_avg) + w3·budget_fraction − penalty(未登录) 取最大(贪心 least-loaded);fan-out 反复取当前最大 ⇒ K 个 session 自然铺到 K 台。
  • 背压(不 thrash):每-tag FIFO(cap=64,high/low 各一条队)。全满 → 不 spawn-and-thrash,返回 202 queued + 位次;空位由心跳到达事件驱动 admit(NOT tick);队满 → 503 capacity + 「加机器或抬 --max-parallel」。
  • 护栏:placement 严格只决定 WHERE;WHAT/HOW-MANY 归 cto/用户,调度器绝不注入额外并行;不长 tick / DAG executor(否则撞 deferred ccteam-flow);placement sticky(一个 sid 生命周期内不迁移)。
  • 用户原例:高配机 --tags deploy,e2e,stress --class high 跑端到端部署+压测;低配机 --tags design,prototype --class low 跑需求讨论+原型 — 同时跑、各扬所长,从同一个 Telegram chat 驱动。并行天花板:从「一台机容量」升成 Σ(per-node session 容量)。
