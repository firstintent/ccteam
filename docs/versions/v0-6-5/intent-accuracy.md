## Notes on attribution

- **`mock` mode** runs the static routing table inside `intent-accuracy.sh`
  (mirrors `skills/ccteam/SKILL.md` Step 1 priority top-down keyword table).
  This validates that the spec the dispatcher LLM is told to follow can
  itself hit >=0.90 on the corpus — if it can't, the corpus or the table
  is wrong, not the LLM.
- **`--real` mode** invokes `claude --print` once per query (Sonnet by
  default; ~$0.10 / 2-3 min wall for the full 50). Use this before each
  V0.x ship to catch dispatcher drift in the real LLM response.
- Any failure with `predicted=other` is a Step-7 fallback miss — the LLM
  (or the mock table) couldn't pin the intent and would have served the
  user the 4-options dialog instead of routing directly.

### Known mock-mode quirks

- `stop the overnight-builder workflow` lands on `create-workflow` in mock
  mode because the static table's substring scan hits `overnight` before
  it sees the `stop` action verb. The SKILL.md Step 1 priority spec leaves
  this case ambiguous: the user-facing LLM should resolve it via the
  歧义启发式 (有具体 slug 提及 → status-debug). Mock table cannot replicate
  that heuristic without an LLM round-trip; `--real` mode is the canonical
  check for this class of edge case.
