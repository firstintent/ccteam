STABILITYUX(本版新维) 硬门best-effort INOUT 对抗审查修正

〇、一句话

把核心环路 — inbound(IM/web)→ spawn/resume session → agent 干活(可 HITL)→ turn 完通知 → 人 steer — 打到「无聊地可靠 + 用着顺手」:一条 golden-path soak(按 vendor 分轴)量稳定,一组 UX 门量体验。不是加功能,是让这条已有的路在真实失败态下零意外、对用户零困惑、失败时看得见。

🔒 铁律 — 双轴,只硬化 + 打磨已有面

v0.8.10 只在两条同等的轴上把「已存在的核心环路」打到生产级:STABILITY 零丢/零串/零静默失败/零 STUCK 误报/resume 精确/扛重启·suspend·断网  &  UX 同一条环路的用户体验(失败看得见读得懂、随时看到 session 在干嘛/卡没卡/花多少、报错可操作、上手知道「然后呢」、模型支持诚实标注)。

最锋利的 IN/OUT 测试:「本版后,用户有没有一件以前做不到、现在能做的新事?」
有 → OUT(= feature,出局)   同一件事变可靠/看得见/清楚/报错友好 → IN

只承认 2 个 micro-exception(D9-② 模型未验证 warn、D9-③ 每 session 活动态 label),其余新增用户可达能力一律出局。reframe:UX 大部分不是新工作 — 它是「已有可靠性不变式」的用户可见的脸(「零静默失败」本身就是 UX),折叠进 D4/D5/D6,不另开无底 UX pass。

一、核心环路 + 不变式(永不破)

IM/web 消息 ──▶ spawn 或 resume session ──▶ agent 干活(可 HITL)──▶ turn 完成通知回 chat ──▶ 人给方向 ──┐ ▲ │ └────────────────────────────────────────────────────────────────────────────────────────────┘
  • 零丢数据 · 每条 turn 入/出都不丢;通知不丢、不错投。
  • 零串台 · 会话间历史/事件严格隔离;同一 cwd 多 session + Task 子 agent 时回复只投自己 chat。
  • 零静默失败 · 失败必有用户当场可见的人话信号;且健康但安静的 session 不得误报(反假阳)。 STABUX(D8 的脸)
  • 零误报 · STUCK 不撒谎;单一 file-backed(progress.jsonl)stall 真相,CLI 与 web 读同一分类函数。
  • resume 精确续 · Claude=byte-exact reattach + 上下文续;Codex=按 id codex resume 重放、不重复投递。
  • 扛得住 · daemon 重启 / 空闲释放 / host suspend / 断网重连 — 都不丢不串不卡;restart 后所有 live session 按 sid 重挂。
  • 默认成立 · 默认 rmux × {claude, codex} 下成立,不靠 tmux 兜底。Codex 是架构 best-effort tier。
  • (UX)零困惑 · 用户不必读代码/日志就知道:在哪个 project/session、它在干嘛、卡没卡、花多少、下一步、失败怎么办。 UX

二、交付物 D1–D9 · D1–D7 稳定性,D8–D9 UX(同等新维,盖在 D4/D5/D6 上,不另开 track)

D1 golden-path soak 框架 核心交付 + 门
e2e + fault-injection harness,跑核心环路 + 注故障。复用已有 8 个 reconnect/resume harness,不另起炉灶。
验收:CI-fake 切片硬门(kill daemon/杀 pane/断网,确定性)+ 真机 ≤1h 短 smoke 硬门;真机长跑/Codex 长跑 = best-effort。
D2 收口 backend 抽象 病根 a
所有绕过 ProcessBackend 直连 tmux 的路径改走抽象(bug5 peek 同类病根)。
验收:guard 测试 — tmux 字面只许白名单文件,PATH 注入假 tmux 让白名单外被调即 panic。
D3 收口 session 身份 病根 b
所有按 role(而非 sid)keyed 的残留改按 gateway session-map;chat_session_reset* 三 builder 收 sid。
验收:同 role 多 session 不串 + roleless 端到端有回复 + 多 session-per-cwd transcript 选对目标(bug6 专测守)。
D4 修 state 失同步 + 单一 stall SoT 病根 c
两套 stall 概念收敛成 file-backed progress.jsonl 单一真相;每状态字段必有 writer。
验收:CLI stall_verdict 与 web 读同一真相 + 同一 ccteam-core 分类函数,同 fixture 断相等。
D5 边界可靠性工程 timeout/retry/幂等
每个跨进程/网络边界给定 {超时<播报截止, 重试+退避, 幂等键}(§五.x 表)。
验收:daemon restart 后 ≥2 sid 重挂 / recreate 失败诚实 reset 带 sid / ledger 重放幂等 / 入站断网不丢不重。
D6 通知可靠 + flake 先定位 原语 3
先 stress 定位 flake(产品缺陷 vs 测试 timing 都 in-scope),修 outbound-ledger flake + file-send gap。
验收:每 turn-done 必达对的 chat;多 session-per-cwd 不串台;0-flake = D6 出口门(连跑 ≥10 次绿)。
D7 核心环路 bug backlog + 死代码 收口
pull dev 重列未修项;死代码逐项 grep 核实 caller 集再删。
验收:每行带真实 caller 集 + 删除验收 cargo build/test ≥ 基线(杜绝「按 PRD 删了反而 red build」)。
D8 零静默失败的用户信号 UX 同等新维
「失败必有可见信号」从「log 里能查」升级成「用户当场看见、是人话」。枚举核心环路全部失败态 → 每个映射一条人话消息(见下方失败表 + mockup)。
验收:该失败 → 每通道恰好一条非空、含 next-step 的消息;每个 new-emit 行带反假阳测试(健康但安静不误报)。
D9 上手 + 模型诚实 + 可观测性 + 文案 UX 同等新维
① 上手引导(init 后「然后呢」)② 模型支持诚实(非 Claude 模型 warn)③ 可观测性(每 session 活动态)④ 错误文案打磨。全是打磨已有面。
验收:上手零未文档化步骤;模型 warn 谓词正确;CLI/web 读同一 stall 真相;错误文案过正则白/黑名单。
