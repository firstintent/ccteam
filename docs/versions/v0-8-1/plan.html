这是什么 / 怎么用

把 im.html 里那套 v8.1 架构在 ccteam 真仓库里实现 —— 「云 Claude Code / Codex + IM」:一个常驻 daemon 当 IM⇄session 路由网关,驱动 Claude(tmux)和 Codex(app-server)常驻 session,手机收发、切项目/会话。v8.1 不做手机批准,agent 跑 --dangerously-skip-permissions(无批准门)。

用法: 新 session 里 /goal 本文件。严格按 P0 → P6 顺序,每个 phase 必须先跑通它的「✅ 验收」命令(全绿)才进下一个。所有验收全绿 = 完成。被打断可从"第一个没过验收的 phase"续做。

贯穿红线(每个 phase 都守)

  • 不退步 baseline:每 phase 末 cargo test --workspace --locked --no-fail-fast --exclude ccteam-web 的 pass 数 ≥ 起手数(起手先记下基线)。
  • clippy 0 warning + cargo fmt --all --check 干净(收尾 P6 强制,过程中尽量保持)。
  • skip-permissions:所有 spawn 的 agent 带 --dangerously-skip-permissions(Codex 用其等价 yolo/bypass);不写任何批准回路。
  • 4 个抽象边界现在就留对(细节见 im.html「执行层」「整体架构」):HarnessAdapter(drive)/ ProcessBackend(host)/ CanonicalEvent / ApprovalIR(v8.1 只留类型占位,不实现批准)。
  • 验证优先用确定性 fake:CCTEAM_CLAUDE_BIN / CCTEAM_CODEX_BIN 指向打桩二进制(吐固定 stream-json / JSON-RPC),使测试 CI 可跑、不依赖真 claude/codex;真二进制只在 P5 的可选 smoke 跑。
  • 命名已定:执行层 crate = ccteam-harness(非 mux);supervision trait = ProcessBackend(tmux 专属方法只在 TmuxBackend)。
起手第一件事(记基线):
